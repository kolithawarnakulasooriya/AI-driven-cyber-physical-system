# Feature Usage Guide

This skill documents a repeatable, step-by-step procedure for introducing and using newly added features in the AI-driven cyber-physical system project. It ensures consistent onboarding, reduces ambiguity, and provides a verifiable checklist for adopters.

## When to Use
- A new feature has been merged into the main branch.
- You need to onboard team members or users to the new functionality.
- You want a structured, auditable method for training or documentation.

## Prerequisites
- Access to the repository with the latest code (`git pull`).
- The new feature must be documented in the release notes or changelog.
- Required dependencies (e.g., specific library versions, environment variables) should be installed as per the project’s `environment.yml` or equivalent.
- Basic familiarity with the project’s directory layout and tooling (`terminal`, `read_file`, etc.).

## Procedure
1. **Review Release Notes**  
   Locate the announcement of the new feature in `CHANGELOG.md` or the merge‑commit message. Note the feature name, purpose, and any required configuration.

2. **Verify Installation**  
   Ensure the environment reflects the latest dependencies:  
   ```bash
   conda env update -f environment.yml --prune
   conda activate ee506
   ```  
   Confirm the feature’s entry point (e.g., a Python module or CLI command) is available.

3. **Read the Feature Documentation**  
   Open the relevant markdown file in `docs/features/` or the generated API docs. Identify required input formats, optional arguments, and examples.

4. **Run a Quick‑Start Example**  
   Execute the provided starter command or script:  
   ```bash
   python -m uvicorn sensorhub.app:app --reload   # Example for sensor hub
   ```  
   Or, if the feature provides a CLI:  
   ```bash
   sensorhub-cli --configure --output results/
   ```

5. **Validate Output**  
   Check that the expected result appears (e.g., a functioning UI at `http://localhost:8000`, a CSV output file, or a log entry). Use `read_file` or `terminal` to inspect outputs.

6. **Incorporate Into Workflows**  
   Update any relevant scripts, CI pipelines, or test suites to include the new feature. Add usage snippets to README sections as needed.

7. **Document Learnings**  
   Add a brief “How‑to‑Use” subsection to the project’s main README, referencing the steps above. Include code snippets or command examples verbatim.

8. **Iterate & Collect Feedback**  
   After initial usage, gather feedback from teammates. If issues arise, update the documentation or the feature implementation accordingly.

## Verification
- Run the step‑by‑step commands listed in the procedure and confirm each completes without error.  
- Capture the output of the final verification command (e.g., `curl -s http://localhost:8000/health | grep OK`) to prove the feature operates as intended.  
- Ensure the updated README renders correctly (preview in a browser or via `pandoc`).

## Quick Reference
- `git log --oneline -1` – view latest commit summary.  
- `conda activate ee506` – activate the project environment.  
- `python -m uvicorn sensorhub.app:app --reload` – launch the sensor hub simulator.  
- `sensorhub-cli --configure` – initialize the feature’s configuration.

## Pitfalls
- Skipping the environment update may lead to missing modules.  
- Using outdated example code can cause runtime errors; always reference the latest docs.  
- Forgetting to adjust CI pipelines can result in failed builds when the new feature is exercised.
